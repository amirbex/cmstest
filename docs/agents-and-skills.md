# سیستم ایجنتیک، مهارت‌ها و پرامپت‌ها

راهنمای کامل معماری هوش مصنوعی AtoZ Content Studio v6.

---

## ۱. تصویر کلی

سیستم از سه لایه‌ی مستقل ساخته شده که هرکدام جدا قابل تغییر است:

```
┌─────────────────────────────────────────────────────────┐
│  پرامپت‌ها (system_prompt در SQLite)                       │
│  «نقش و قواعد کلی هر ایجنت» — از اتاق پرامپت‌ها ویرایش می‌شود │
└──────────────────────────┬──────────────────────────────┘
┌──────────────────────────┴──────────────────────────────┐
│  مهارت‌ها (skills/<id>/SKILL.md روی دیسک)                  │
│  «دانش اجرایی تخصصی» — به ایجنت‌های مشخصی تزریق می‌شود        │
└──────────────────────────┬──────────────────────────────┘
┌──────────────────────────┴──────────────────────────────┐
│  دانش‌پایه (knowledge-base/*.md)                          │
│  «حقیقت برند» — همیشه، به همه‌ی ایجنت‌ها                     │
└──────────────────────────┬──────────────────────────────┘
                           ↓
              ┌────────────────────────┐
              │  زنجیره‌ی مدل + اعتبارسنجی │
              └────────────────────────┘
```

هر فراخوانی مدل به این شکل ساخته می‌شود:

```
پرامپت مادر ایجنت
  + دانش‌پایه (همه)
  + مهارت‌هایی که ایجنت را در front-matter خود نام برده‌اند
  + داده‌ی زنده (وضعیت، موضوع، کانسپت)
  + اسکیمای خروجی
        ↓
   مدل ← zod validation ← یک تلاش اصلاحی ← در نهایت fallback آفلاین
```

## ۲. ایجنت‌ها

چهار ایجنت وجود دارد. «ایجنت» یعنی یک نقش با پرامپت مشخص، مهارت مشخص،
قرارداد خروجی مشخص و سهمیه‌ی مستقل — نه یک پرسونای چت.

| ایجنت | نقش | پرامپت مادر | خروجی | حق اقدام |
| --- | --- | --- | --- | --- |
| `ATOOZ_CORE` | دستیار فرماندهی | `ATOOZ_CORE` | `AtoozDecision` | ✅ بله |
| `MKT_DIR` | مدیر بازاریابی | `IDEATION_STRATEGY` | `ConceptResponse` | ❌ نه |
| `SCRIPT_DIR` | کارگردان محتوا | `UNIFIED_CONTENT_FACTORY` | `FactoryResponse` | ❌ نه |
| `SEO_EDITOR` | ویراستار سئو | `SEO_EDITOR` | فیلد `articleHtml` | ❌ نه |

### قاعده‌ی مهم: تنها یک ایجنت حق اقدام دارد

`ATOOZ_CORE` تنها ایجنتی است که `canAct: true` دارد. بقیه فقط **متن تولید می‌کنند** و
نمی‌توانند چیزی را تأیید یا رندر کنند. این عمدی است و با تست قفل شده
(`tests/agents.test.js` → «exactly one agent is allowed to act»).

حتی برای آتوز، هر اقدامی که عوارض جانبی داشته باشد `requiresConfirmation: true`
برمی‌گرداند و دکمه‌ی تأیید در رابط نمایش داده می‌شود. مدل هرگز مستقیم نمی‌نویسد.

### مشاهده و اشکال‌زدایی ایجنت‌ها

اتاق جدید **«ایجنت‌ها و مهارت‌ها»** (`#skills`) برای هر ایجنت نشان می‌دهد:
- پرامپت مادر و قرارداد خروجی
- مهارت‌های تزریق‌شده و حجم زمینه (کاراکتر)
- تعداد اجرا، آخرین زمان و تأخیر
- دکمه‌ی **«دیدن پرامپت نهایی»** — دقیقاً متنی که به مدل می‌رود

```bash
curl localhost:4000/api/agents
curl localhost:4000/api/skills/preview/SCRIPT_DIR
```

## ۳. مهارت‌ها (Skills)

### ساختار هر مهارت

```
skills/<id>/SKILL.md
```

```markdown
---
id: reel-structure                    # شناسه یکتا
title: ساختار ریلز عمودی              # عنوان فارسی
capability: تبدیل ایده به صحنه         # یک خط توضیح
agents: SCRIPT_DIR                    # به کدام ایجنت‌ها تزریق شود
inject: true                          # false = خاموش (فایل می‌ماند، تزریق نمی‌شود)
tags: reel, timeline
---

# متن مهارت
…قواعد، جداول، مثال خوب و بد…
```

`front-matter` بین دو خط `---` است. اگر `agents` خالی باشد، مهارت به **همه** تزریق می‌شود.

### مهارت‌های فعلی

| شناسه | چه می‌آموزد | ایجنت‌ها |
| --- | --- | --- |
| `persian-copy` | نیم‌فاصله، نشانه‌گذاری، لحن، ساخت قلاب | همه |
| `reel-structure` | ریتم ۵ بخشی ریلز، قواعد متریک و نریشن | SCRIPT_DIR |
| `carousel-blueprint` | قوس روایی ۱۰ اسلاید و قواعد متن | SCRIPT_DIR |
| `data-storytelling` | انتخاب نمودار درست، قواعد داده‌ی معتبر | MKT_DIR, SCRIPT_DIR |
| `jalali-scheduling` | هفته‌ی ایرانی، پنجره‌های طلایی انتشار | ATOOZ_CORE, MKT_DIR |
| `seo-article` | ساختار HTML معنایی مقاله | SEO_EDITOR |

### افزودن مهارت جدید — بدون تغییر یک خط کد

```bash
mkdir -p skills/my-skill
cat > skills/my-skill/SKILL.md <<'EOF'
---
id: my-skill
title: مهارت تازه من
agents: SCRIPT_DIR
inject: true
---

# قواعد
- هر صحنه حداکثر ۳ آیتم داشته باشد.
EOF

# نیازی به ری‌استارت نیست:
curl -X POST localhost:4000/api/skills/reload
```

از این لحظه هر فراخوانی `SCRIPT_DIR` این متن را با خودش می‌برد.

### بودجه‌ی زمینه

هر مهارت حداکثر ۲۴۰۰ کاراکتر و کل زمینه هر ایجنت حداکثر ۱۴٬۰۰۰ کاراکتر است
(`MAX_TOTAL_CHARS`). اگر مهارت‌ها بیشتر شوند، بقیه بی‌صدا حذف نمی‌شوند —
در `buildContext` شمارش می‌شود و تست `context stays inside the prompt budget`
جلوی انفجار پرامپت را می‌گیرد.

## ۴. پرامپت‌ها

پرامپت‌های مادر در جدول `system_prompt` ذخیره می‌شوند (SQLite، نه فایل) و از
اتاق **پرامپت‌ها** (`#prompts`) ویرایش می‌شوند.

- هر ذخیره `version` را یک واحد بالا می‌برد.
- تغییر بلافاصله در فراخوانی بعدی اثر می‌کند — بدون ری‌استارت.
- مقادیر خالی و کلیدهای نامعتبر رد می‌شوند (`400 VALIDATION`).
- هر ذخیره در `event_log` ثبت می‌شود.

```bash
curl localhost:4000/api/prompts
curl -X POST localhost:4000/api/prompts \
  -H 'content-type: application/json' \
  -d '{"ATOOZ_CORE":"متن جدید…"}'
```

### تفاوت پرامپت و مهارت — چرا دو جا؟

| | پرامپت | مهارت |
| --- | --- | --- |
| محل | SQLite | فایل `.md` |
| چه چیزی | «تو کی هستی، چه کاری مجاز است» | «چطور این کار را درست انجام بده» |
| ویرایش | رابط کاربری | ادیتور متن |
| نسخه‌بندی | خودکار در DB | گیت |
| دامنه | یک ایجنت | چند ایجنت |

قاعده‌ی سرانگشتی: **شخصیت و مجوز → پرامپت. دانش فنی و سبک → مهارت.**

## ۶. نحوه کار با مدل‌های هوش مصنوعی

### سه حالت، انتخاب خودکار

```
کلید GEMINI_API_KEY وجود دارد؟   → cloud
وگرنه ATOZ_LOCAL_AI_URL وجود دارد؟ → local-llm
وگرنه                              → local (قالب آفلاین)
```

حالت در `/api/state`، `/api/agents` و گوشه‌ی اتاق مهارت‌ها نمایش داده می‌شود.

#### الف) ابری — Google Gemini

```bash
npm install @google/genai            # وابستگی اختیاری، همراه پکیج نیست
echo 'GEMINI_API_KEY=...' >> .env
```

زنجیره‌ی مدل قابل تنظیم است (اگر یکی ۴۰۴ یا ۴۲۹ بدهد، برای مدتی کنار گذاشته می‌شود):

```bash
ATOZ_MODEL_CHAIN=gemini-2.5-flash,gemini-2.5-flash-lite,gemini-2.0-flash
```

#### ب) مدل محلی — پیشنهاد اصلی برای کار آفلاین

هر سروری که API سازگار با OpenAI داشته باشد کار می‌کند:

```bash
# Ollama (ساده‌ترین)
ollama pull qwen2.5:7b-instruct
ollama serve

# .env
ATOZ_LOCAL_AI_URL=http://localhost:11434/v1
ATOZ_LOCAL_AI_MODEL=qwen2.5:7b-instruct
```

گزینه‌های دیگر با همان متغیرها:

| سرور | URL |
| --- | --- |
| LM Studio | `http://localhost:1234/v1` |
| llama.cpp server | `http://localhost:8080/v1` |
| vLLM | `http://localhost:8000/v1` |
| Jan | `http://localhost:1337/v1` |

**مدل پیشنهادی:** برای فارسی، `qwen2.5:7b-instruct` یا بالاتر. مدل‌های زیر ۷ میلیارد
پارامتر در تولید JSON فارسی خطای ساختاری زیادی می‌دهند (سیستم آن را می‌گیرد و به
قالب آفلاین می‌افتد، اما کیفیت پایین می‌آید).

هزینه‌ی مدل محلی در پنل سهمیه صفر نمایش داده می‌شود — چون واقعاً صفر است.

#### ج) قالب آفلاین

هیچ تنظیمی لازم نیست. خروجی از قالب‌های فارسی درون‌کد ساخته می‌شود: کاملاً معتبر،
قابل رندر، و قابل ویرایش در استودیو. کل خط تولید (ایده → تأیید → رندر → گالری)
بدون هیچ مدلی کار می‌کند.

### اعتبارسنجی خروجی مدل — چرا مدل نمی‌تواند سیستم را بشکند

```
پاسخ مدل
   ↓ استخراج JSON (تحمل ``` و متن اضافه)
   ↓ zod .safeParse() با اسکیمای contracts
   ├─ معتبر → استفاده
   └─ نامعتبر → یک تلاش اصلاحی با متن خطا
                 └─ باز هم نامعتبر → مدل بعدی در زنجیره
                       └─ همه شکست → قالب آفلاین
```

هرگز `JSON.parse` بدون اسکیما انجام نمی‌شود. یک مدل نمی‌تواند شناسه‌ی نامعتبر،
وضعیت ناموجود یا متن ۵۰ کیلوبایتی داخل دیتابیس بنویسد.

### اندازه‌گیری و سهمیه

هر فراخوانی در دو جدول ثبت می‌شود:

- `quota_usage` — مصرف روزانه به تفکیک مدل (درخواست، توکن، هزینه)
- `agent_run` — تاریخ هر اجرا (ایجنت، مدل، وضعیت، توکن، تأخیر، خطا)

در اتاق **نظارت** (`#monitor`) تب «سهمیه و مصرف» این‌ها را نشان می‌دهد.
وضعیت‌های ثبت‌شده: `ok`، `invalid-json`، و شکست‌ها.

## ۷. حلقه‌ی ایجنتیک واقعی

سیستم «ایجنت خودمختار» نیست و عمداً نیست. جریان این است:

```
۱. انسان موضوع می‌دهد                    (اتاق فکر)
۲. MKT_DIR سه کانسپت می‌سازد              (خواندن + تولید)
۳. انسان یکی را انتخاب می‌کند              ← دروازه‌ی انسانی
۴. SCRIPT_DIR بسته‌ی کامل می‌سازد          (خواندن + تولید)
۵. محتوا در وضعیت blueprint_pending ذخیره می‌شود
۶. انسان تأیید می‌کند                     ← دروازه‌ی انسانی
۷. صف رندر (بدون مدل، فقط موتور گرافیک)
۸. انسان در تقویم زمان‌بندی می‌کند
۹. انتشار و ثبت متریک                     ← حلقه بازخورد
```

دو دروازه‌ی انسانی اجباری است: **تأیید محتوا** و **انتشار**. مدل هیچ‌گاه مستقیم
منتشر نمی‌کند. دلیل: انتشار خطا در برند گران‌تر از تأخیر است.

حلقه‌ی بازخورد بسته است چون متریک‌های ثبت‌شده (نرخ ذخیره، CTR، نسبت تماشا) در
اتاق بینش به شکل قیف نمایش داده می‌شوند و می‌توانند ورودی چرخه‌ی بعدی باشند.

## ۸. مرجع کامل API

| مسیر | کار |
| --- | --- |
| `GET /api/agents` | فهرست ایجنت‌ها + وضعیت AI |
| `GET /api/skills` | فهرست مهارت‌ها و دانش‌پایه (بدون متن کامل) |
| `GET /api/skills/:id` | متن کامل یک مهارت |
| `POST /api/skills/reload` | بازخوانی از دیسک |
| `GET /api/skills/preview/:agentId` | زمینه‌ی نهایی یک ایجنت |
| `GET /api/prompts` | پرامپت‌های مادر |
| `POST /api/prompts` | ذخیره (نسخه جدید) |
| `GET /api/quotas` | مصرف و تاریخ اجراها |
| `POST /api/ai/concepts` | تولید کانسپت (MKT_DIR) |
| `POST /api/ai/generate` | تولید بسته (SCRIPT_DIR) |
| `POST /api/atooz/chat` | گفت‌وگو با دستیار (ATOOZ_CORE) |

## ۹. عیب‌یابی

| نشانه | علت | راه‌حل |
| --- | --- | --- |
| زمینه ۰ کاراکتر در اتاق مهارت‌ها | پوشه‌های `skills/` و `knowledge-base/` نیستند | آن‌ها را بساز یا از مخزن بکش |
| مدل محلی جواب نمی‌دهد | `ATOZ_LOCAL_AI_URL` تنظیم نشده یا سرویس خاموش است | `curl $ATOZ_LOCAL_AI_URL/models` |
| پیام «مدل ابری در دسترس نبود» | کلید نامعتبر یا سهمیه تمام | عادی است — قالب آفلاین جواب می‌دهد |
| خروجی همیشه قالب آفلاین است | JSON مدل معتبر نبود | لاگ `invalid-json` را در اتاق نظارت ببین؛ مدل بزرگ‌تر امتحان کن |
| مهارت جدید دیده نمی‌شود | کش | `POST /api/skills/reload` |
| پرامپت تغییر کرده اما اثر ندارد | در حالت آفلاین مدل خوانده نمی‌شود | طبیعی است؛ پرامپت فقط در حالت cloud/local-llm اثر دارد |
