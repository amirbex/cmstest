# گزارش بررسی فنی، امنیتی و بصری پروژه

## AtoZ.FnB Content CMS — نسخه ۵.۰

> مرجع بررسی: `atoz-content-cms-v5.0.zip` (تنها محتوای مخزن) — ۱۰۷ فایل، ~۲۹۰۰ خط کد مؤثر
> روش کار: استخراج کامل آرشیو → نصب واقعی وابستگی‌ها → اجرای واقعی سرور Node و موتور Python → فراخوانی همه‌ی مسیرهای API با درخواست‌های واقعی (شامل تست‌های نفوذ هدفمند) → بررسی استاتیک کد و تایپ‌چک TypeScript.

## بخش ۱ — پروژه در یک نگاه

### ساختار واقعی

| لایه | فایل | حجم | نقش |
|---|---|---|---|
| داشبورد + کل منطق UI | `src/dashboard/index.html` | ۷۰ KB / ۱۲۰۱ خط | ۹ «اتاق» + کلاینت آتوز + استودیو |
| API | `src/server/server.js` | ۱۳.۸ KB | Express، ۲۰ اندپوینت، صف رندر FIFO |
| «دیتابیس» | `src/core/relational-db.js` | ۱۷.۶ KB | یک فایل JSON + منطق دامنه |
| ایجنت‌ها | `src/ai-agents/*.js` | ~۲۶ KB | روتر مدل، ارکستراتور، آتوز، صدا |
| رندر | `src/render-engine/**` | ~۱۵ KB | ۳ قالب Remotion (Reel/Carousel/Cover) |
| موتور رسانه | `python-engine/app.py` | ۶۷ خط | TTS و Whisper (FastAPI) |

**معماری فعلی:** یک مونولیت دو-زبانه (Node + Python) با «دیتابیس» فایل‌محور، رابط کاربری تک‌فایلی بدون build، و یکپارچه‌سازی مستقیم با Gemini از طریق `@google/genai`.

### نقاط قوت واقعی (این را از دست ندهید)

1. **دروازه‌ی «Blueprint → تأیید → تولید»** منطق درستی است. جدا کردن «ایده» از «تولید» و از «انتشار» ستون فقرات یک CMS محتوایی حرفه‌ای است و اینجا به‌درستی با سه وضعیت `blueprint_pending / approved_for_production / produced / published` مدل شده.
2. **بهبود کلیدی نسخه ۵: ثبت JSON بدون مصرف توکن.** تبدیل فایل JSON آماده به رکوردهای دامنه، یک بهینه‌سازی اقتصادی بسیار درست است (هزینه‌ی تولید متن را از توکن API به «یک فایل آماده» منتقل می‌کند).
3. **هویت بصری برند جدی گرفته شده.** `brand-config.json` با ۶ زیربرند، رنگ اختصاصی، `mode: dark/light` و مسیر دارایی‌ها — این سطح از سیستم‌مندی در پروژه‌های مشابه کم دیده می‌شود.
4. **قالب‌های Remotion (Reels/Carousel/Cover) واقعاً کدنویسی‌شده‌اند** و با `calculateMetadata` طول ویدئو را به طول صدا گره می‌زنند — ایده‌ی درست.
5. **مدل «۲۴ بلوک» (۳ ماه × ۴ هفته × ۲ بخش)** یک تقویم محتوایی قابل اجراست، نه یک لیست آرزو.
6. **تشخیص گفتار مرورگر + TTS + کلون صدا** به‌عنوان یک حلقه‌ی مکالمه‌ی زنده، هسته‌ی درستی برای دستیار صوتی دارد.

## بخش ۲ — ده ایراد اصلی (به ترتیب شدت)

### ۱) تزریق فرمان سیستمی (RCE) در صف رندر — بحرانی
خروجی تست واقعی من:
```
POST /api/render  {"contentId":"ATZ-X; touch /tmp/INJECTED; echo", ...}
→ /tmp/INJECTED ساخته شد ✅(به نفع مهاجم)
```
`server.js` خطوط ۸۲/۹۰/۹۵: `execAsync(\`npx remotion ... ${outFile} ...\`)`. مقدار `contentId` بدون هیچ اعتبارسنجی‌ای در دستور شل درج می‌شود. هر کسی که به پورت ۴۰۰۰ دسترسی داشته باشد، اجرای کد کامل روی ماشین دارد. (مسیر `propsPath` هم قابل دستکاری است.)

### ۲) API کاملاً بی‌دفاع و «استثناهای شفاف» — بحرانی
- `app.use(cors())` بدون origin → هر سایتی می‌تواند از مرورگر کاربر به این API فرمان بدهد.
- هیچ احراز هویتی وجود ندارد؛ `POST /api/settings/prompts` و `/api/settings/webhooks` و `/api/render` و `/api/voice/add-character` همه باز هستند.
- **تست: توکن تلگرام را نوشتم، سپس `/api/state` آن را برگرداند:**
  `webhooks: {'telegramBotToken': 'SECRET_TOKEN_123'}` → نشت اعتبارنامه به هر خواننده‌ی state.
- خطاها با `err.message` خام به کلاینت برمی‌گردند (نشت مسیرها و ساختار داخلی).

### ۳) امنیت فایل: آپلود خارج از پوشه‌ی مجاز + XSS ذخیره‌شده — بالا
- `POST /api/assets/upload` با `folder=../../../../tmp/escaped` فایل را در `/home/user/tmp/escaped/...` نوشت (تست شده). یعنی نوشتن فایل در هر مسیری که پروسه دسترسی دارد؛ با `filename` دلخواه، امکان نوشتن `.html`/`.svg` و XSS هم هست.
- داشبورد همه‌چیز را با `innerHTML` و template string می‌سازد: `title`, `body`, `reply` مدل، و پرامپت‌ها. تست: پرامپت `<img src=x onerror=alert(1)>` را ذخیره کردم و در `/api/state` دست‌نخورده برگشت → **XSS ذخیره‌شده از سمت مدل هم ممکن است** (کافی است مدل خروجی مخرب بدهد یا JSON آپلودی آلوده باشد).

### ۴) «دیتابیس» فایل JSON بدون قفل و بدون تراکنش — بالا
`loadDb` کل فایل را می‌خواند، `saveDb` کل فایل را بازنویسی می‌کند؛ هر اندپوینت خودش load/save می‌کند. تست هم‌زمانی من با ۵ درخواست موازی، ۵ رکورد را سالم نگه داشت، اما ساختار «read-modify-write» بدون قفل یعنی با رندر طولانی + چند کاربر، **آخرین نویسنده برنده است و داده‌ی دیگران پاک می‌شود**. علاوه بر این با رشد محتوا (هر بلوک ۲۴، هر رکورد شامل کل plan) فایل به چند ده مگابایت می‌رسد و هر `refreshState` همه‌ی آن را به مرورگر می‌فرستد.

### ۵) منطق دامنه اشتباه: دو برابر شدن تحویل‌ها و شمارنده‌های هدر رفته — بالا
در `ingestWeeklyPuzzleJson` اول یک حلقه روی `content_ideas` رکورد می‌سازد، بعد حلقه‌ی دوم روی `deliveries` **دوباره** `createBlueprintRecord` صدا می‌زند. نتیجه‌ی واقعی تست: **۲ ایده → ۴ تحویل** (دو رکورد یتیم با `plan` خالی). ضمناً `db.counters` از ۱ به ۵ رفت چون `createBlueprintRecord` حتی وقتی `explicitContentId` می‌دهید باز شمارنده را افزایش می‌دهد، و `asset_id` رکورد تحویل به asset اشتباه اشاره می‌کند (`ATZ-A-000003` برای `ATZ-C-100001`).

### ۶) نبود اعتبارسنجی ورودی در هیچ لایه‌ای — بالا
`zod` در `package.json` هست اما **هیچ‌جا import نشده**. نتیجه: `POST /api/render {}` باعث خطای مبهم `the "data" argument must be of type string ... Received undefined` می‌شود؛ `POST /api/puzzle/upload-block` با بدنه‌ی نامعتبر مستقیماً به `for (const idea of ideas)` می‌رسد؛ اعداد `counts` در UI می‌توانند `-5` یا `abc` باشند. هیچ schema‌ای برای قرارداد JSON بلوک، خروجی مدل (`JSON.parse(res.text)` بدون try) و بدنه‌ی API وجود ندارد.

### ۷) وابستگی سخت به ویندوز + کلید API = پروژه در عمل اجرا نمی‌شود — بالا
- `voice-engine.js:51`: fallback نهایی `powershell + System.Speech` است. روی لینوکس/مک/Docker **کل مسیر صدا می‌شکند** (تست شد: `/bin/sh: 1: powershell: not found`).
- `server.js` و `remotion.config.ts`: مسیرهای `C:\Program Files\...chrome.exe` هارد‌کد شده‌اند.
- `setup-v5.0.ps1` فقط PowerShell است؛ هیچ نسخه‌ی bash/Docker وجود ندارد.
- `model-router.js` خطوط ۲۰-۴۱: در زمان import، ۶ پورت پروکسی محلی (۱۰۸۰۹/۷۸۹۰/…) را اسکن می‌کند و در صورت یافتن، `globalThis.fetch` را globals عوض می‌کند. این یک hack شخصی است که در محیط ابری/CI رفتار غیرقابل پیش‌بینی ایجاد می‌کند.
- بدون کلید، `/api/agency/expand-concepts` و `/api/atooz/chat` هر دو با `fetch failed` می‌افتند و **هیچ مسیر demo/offline** وجود ندارد.

### ۸) زنجیره‌ی صدا و زیرنویس اسمی است، نه واقعی — متوسط تا بالا
- نام مدل‌ها خیالی‌اند: `gemini-3.5-flash-lite`, `gemini-3.8-flash`, `gemini-4-hydrogen`, `gemini-3.8-flash-tts` در فهرست سهمیه‌ها هستند اما همین نام‌ها به API واقعی فرستاده می‌شوند → خطای 404 و fallback.
- اگر `edge-tts` (که خودش به شبکه‌ی مایکروسافت نیاز دارد) بترکد، FastAPI خطای 500 خام می‌دهد و هیچ try/except ندارد.
- زیرنویس‌ها «حدسی» هستند (`buildHeuristicCaptions`: تقسیم خطی زمان روی تعداد کلمه). یعنی karaoke دقیقاً کلمه‌ای نیست.
- `whisper` در `/transcribe` **در هر درخواست مدل را دوباره می‌سازد** (چند ثانیه/چند صد مگابایت هر بار).

### ۹) صف رندر: شکننده، غیرقابل مشاهده، بدون مهلت — متوسط تا بالا
- `execAsync` بدون `timeout` و بدون محدودیت حجم خروجی؛ یک رندر گیرکرده کل صف را قفل می‌کند.
- فایل props مشترک (`outputs/render-props.json`) بین همه‌ی جابها → در صورت شکست وسط کار، props جاب بعدی را بازنویسی می‌کند.
- شکست رندر فقط در لاگ می‌ماند؛ **کلاینت هرگز مطلع نمی‌شود** و `asset.status` هم `produced` نمی‌شود، پس کاربر گیر می‌کند.
- `POST /api/render` تا پایان رندر درخواست را باز نگه می‌دارد (بدون job id / polling / WS) — دقیقاً خلاف چیزی که برای یک صف لازم است. بسته‌ی `ws` نصب شده اما استفاده نشده.
- هیچ retry، هیچ اولویت، هیچ کنسلی برای جاب، هیچ محدودیت هم‌زمانی بر اساس RAM.

### ۱۰) بدهی فنی و تجربه‌ی کاربری: تک‌فایل ۷۰ کیلوبایتی، CDN، و «استودیو»یی که استودیو نیست — متوسط
- **۱۲۰۱ خط HTML/CSS/JS درون‌خطی، بدون build، بدون تست، بدون TypeScript، بدون ماژول.** فقط با `grep` می‌شود در آن ناوبری کرد. Tailwind از `cdn.tailwindcss.com` (نسخه‌ی dev، غیرقابل استفاده در production و offline) لود می‌شود؛ فونت هم از Google Fonts — در محیط بدون اینترنت، کل ظاهر می‌شکند.
- ادعای «درگ‌اند‌دراپ لایه‌ها» در README: **صفر مورد** `draggable/onDragStart` در کد. فقط ورودی عددی X/Y وجود دارد. همین‌طور «تایم‌لاین چندتراکه» فقط سه `<div>` تزئینی است با کلیک روی بلوکها.
- پخش پیش‌نمایش ثابت روی `0.5s` و سقف `00:30` هارد‌کد شده است؛ با ویدئوی ۶۰ ثانیه‌ای هم‌خوان نیست.
- تقویم: روزها با `now + idx` و برچسب «شنبه/یکشنبه…» از پیش تعیین‌شده تولید می‌شوند — **هیچ‌گاه با روز واقعی هفته جلالی هم‌خوان نمی‌شود** (اگر امروز دوشنبه باشد، اولین ستون هم «شنبه» برچسب می‌خورد).
- تطبیق تقویم با `schedule_key.includes('D01')` انجام می‌شود → `D010` هم روی D01 می‌افتد (تست کردم: `true`).
- `scanFolderTree` هر بار که state صدا زده می‌شود کل درخت پوشه‌ها را روی دیسک پیمایش می‌کند؛ `refreshState` هم پس از هر تغییر و `switchRoom` دوباره اجرا می‌شود، بدون کش و بدون debounce.
- هیچ‌کدام از ۴ فایل `skills/*/SKILL.md` و فقط ۱ فایل از `knowledge-base` در آموزش ایجنت خوانده می‌شود، چون `loadKnowledgeAndSkills` فقط فایل‌های سطح اول پوشه را می‌خواند — نه زیرپوشه‌ها. یعنی کل مفهوم «skills» عملاً بی‌اثر است.
- `outputs/` و `public/` در `.gitignore` نیستند و آرشیو، `__pycache__` و فایل‌های صوتی ۷۰۰ کیلوبایتی را هم همراه دارد.
- `npm audit`: ۱۱ آسیب‌پذیری critical (از جمله خود `remotion@4.0.280`), `multer@1.x` مرده، `uuid`, `webpack`, `glob`.
- `tsc --noEmit` شکست می‌خورد (۳ خطا) → یعنی پروژه حتی type-safe نیست.

## بخش ۳ — راهکار هر ایراد (به ترتیب اولویت اجرا)

| # | ایراد | راهکار مشخص |
|---|---|---|
| ۱ | RCE در رندر | `execFile` یا `spawn` با آرایه‌ی آرگومان به‌جای `exec` با رشته. اعتبارسنجی `contentId` با regex `^ATZ-[A-Z]-\d{6}$`. حتی بهتر: از CLI استفاده نکنید و `@remotion/renderer` را مستقیم (`renderStill`/`renderMedia`) فراخوانی کنید. |

| ۳ | آپلود/XSS | پوشه را از یک enum مجاز انتخاب کنید (نه از body). `path.resolve` + بررسی `startsWith(baseDir)`. محدود کردن `filename` و MIME، سقف حجم. در فرانت: `textContent` یا یک تابع `escapeHtml` برای همه‌ی درج‌ها (یا مهاجرت به React). از DOMPurify برای HTML مقاله استفاده کنید. |
| ۴ | دیتابیس JSON | کوتاه‌مدت: قفل با `proper-lockfile` یا صف نوشتن سریالی + نوشتن اتمیک (tmp → rename) + backup روزانه. میان‌مدت: **better-sqlite3** (همگام، سریع، تراکنشی، صفر-کانفیگ) یا Prisma+SQLite. بلندمدت: Postgres اگر چند کاربر/چند ماشین. |
| ۵ | منطق دامنه | ادغام دو حلقه‌ی ingest در یک پاس بر اساس `content_id`؛ عدد `counters` را فقط وقتی `explicit*Id` نبود افزایش دهید؛ `asset_id` تحویل را از رکورد دارایی واقعی بخوانید. نوشتن تست واحد برای `ingestWeeklyPuzzleJson`. |
| ۶ | اعتبارسنجی | `zod` را واقعاً استفاده کنید: `zod` schema برای هر بدنه‌ی API، برای قرارداد `puzzleJson` و برای خروجی مدل (`safeParse` با ۲ بار retry روی JSON نامعتبر). میدل‌ور `validate(schema)` بنویسید. مسیر ۴۰۴/۴۰۰ با پیام دقیق. |
| ۷ | وابستگی به ویندوز | fallback صدا را به `piper` (TTS فارسی آفلاین، CPU) یا `edge-tts` (که کراس‌پلتفرم است) منتقل کنید و Windows SAPI را فقط به‌عنوان پلتفرم‌اختصاصی نگه دارید. مسیر مرورگر را از `env: BROWSER_EXECUTABLE` بخوانید و `npx remotion browser ensure` را در setup اجرا کنید. `docker-compose.yml` + `Makefile` + اسکریپت `setup.sh` اضافه کنید. اسکن پروکسی را به یک `PROXY_URL` صریح تبدیل کنید. حالت `DEMO_MODE=1` با داده‌ی نمونه و پاسخ‌های mock برای مدل و TTS. |
| ۸ | صدا/زیرنویس | فهرست مدل‌ها را از یک پیکربندی واقعی (`GET /models`) بگیرید، نه هارد‌کد. لاگ ۴۰۴ را به `MODEL_NOT_FOUND` نگاشت کنید. Whisper را به یک singleton با `lru_cache` تبدیل کنید و مدل را فقط یک‌بار لود کنید. زیرنویس را از `edge-tts --write-subtitles` یا Whisper واقعی بگیرید تا karaoke واقعی شود. برای TTS هر خطا را به `HTTPException` با پیام فارسی تبدیل کنید. |
| ۹ | صف رندر | مدل جاب: `{id, status, progress, error, outputs}` در DB. `spawn` + `timeout` (مثلاً ۱۰ دقیقه) + `maxBuffer` + کشتن پروسه‌ی فرزند. props هر جاب را در فایل اختصاصی بنویسید و پاک کنید. `GET /api/render/:jobId` برای polling و ارسال رویداد با همان `ws` که نصب شده. ثبت شکست در گالری با دکمه‌ی «تلاش مجدد». |
| ۱۰ | بدهی فنی/UX | مهاجرت UI به Vite + React + TypeScript + Tailwind کامپایل‌شده، تقسیم به کامپوننت‌ها، و شکستن `server.js` به `routes/`, `services/`, `jobs/`. Drag واقعی با `@dnd-kit`. تقویم: `Intl.DateTimeFormat('fa-IR')` برای نمایش + محاسبه‌ی درست شنبه به‌عنوان شروع هفته با `getDay()`. تطبیق با `schedule_key.split('-')[2] === dayCode`. کش `folderTree` با `fs.watch`. اضافه‌کردن `.gitignore`, `eslint`, `vitest`, `tsc --noEmit` در CI. |

## بخش ۴ — پیشنهادهای توسعه (فنی)

### ۴.۱ بازطراحی معماری پیشنهادی

```
apps/
  web/            React + Vite + TS + Tailwind (۱۰ اتاق = ۱۰ روت)
  api/            Fastify یا Express با schema-based validation
    routes/       contents, assets, deliveries, calendar, render, ai, voice
    services/     domain logic (بدون دسترسی مستقیم به DB)
    jobs/         BullMQ/Graphile + worker جدا برای رندر
  worker-render/  فقط Remotion، بدون دسترسی به اینترنت
  worker-ai/      صف ایجنت‌ها + ردیابی هزینه/توکن به تفکیک اجرا
packages/
  contracts/      schemaهای zod مشترک بین web و api (single source of truth)
  brand/          brand-config + توکن‌های دیزاین به‌صورت کد
  remotion-comps/ قالب‌های مشترک
infra/
  docker-compose (api, web, worker, postgres, redis, minio)
```

### ۴.۲ ده توسعه‌ی فنی با ارزش بالا

1. **لایه‌ی Contracts با zod**: یک schema برای `Content`, `Asset`, `Delivery`, `PuzzleBlock`, `RenderJob` که هم API و هم UI و هم پارسر ورودی مدل از آن استفاده کند. بزرگ‌ترین کاهش باگ در این پروژه از همین‌جا می‌آید.
2. **صف واقعی + WebSocket**: `bullmq` (Redis) برای رندر و AI. رویدادهای `job:progress` را با `ws` به UI بفرستید تا نوار پیشرفت واقعی داشته باشید. `ws` الان نصب و بی‌استفاده است.
3. **سرویس AI با کش و بودجه**: کلید `hash(prompt + model)` → پاسخ کش‌شده در SQLite. بودجه‌ی روزانه به تفکیک ایجنت و **توقف خودکار** به‌جای «شمارش قشنگ در UI». هزینه‌ی هر اجرا را به تفکیک ایجنت/محصول ثبت کنید و در داشبورد نمایش دهید. (اینجا «مدیر منابع» فقط یک کارت است، ولی در واقع هیچ سقفی اعمال نمی‌شود.)
4. **آفلاین-اول / خودمیزبان**: TTS با `piper` (فارسی)، ASR با `faster-whisper` (singleton)، ترجمه/متن با Ollama (qwen2.5) به‌عنوان fallback. این پروژه را از «وابسته به یک کلید» به «قابل استفاده در ایران بدون پروکسی» تبدیل می‌کند — که برای مخاطب این پروژه تعیین‌کننده است.
5. **پارسر مقاوم JSON برای مدل**: `responseSchema` بومی Gemini + `safeParse` + retry اصلاحی + «ترمیم» با مدل دوم. الان یک بک‌تیک در پاسخ مدل، کل فرآیند را می‌شکند.
6. **پرامپت‌ها به‌عنوان کد و نسخه‌دار**: `prompts/atooz.v1.md`, `prompts/factory.v3.md` با تاریخچه در git، و ثبت `promptVersion` روی هر رکورد تولیدشده. الان ویرایش پرامپت در UI، بی‌ردپا و غیرقابل بازگشت است.
7. **ورود / نقش‌ها**: حتی یک توکن ساده + نقش `admin/viewer`. مسیر تولید و انتشار باید audit trail داشته باشد: `who, what, when` برای هر تغییر وضعیت.
8. **زیرساخت تست**: `vitest` برای دامنه (ingest، rollover، KPI، تقویم)، `playwright` برای ۹ اتاق، و یک `fixtures/sample-block.json` واقعی. این پروژه الان صفر تست دارد و هر تغییر v6 می‌تواند رگرسیون برگرداند (همان‌طور که تحویل‌های تکراری نشان می‌دهد).
9. **تولید رسانه‌ی واقعی**: `renderStill/renderMedia` از `@remotion/renderer` با `chromiumOptions: { enableMultiProcessOnLinux: true }`, کش props در `outputs/jobs/<id>/props.json`, و خروجی `webm/mp4` با `proRes`/`h264`. برای کاروسل، رندر موازی ۵ اسلاید با `Promise.all` و سقف هم‌زمانی ۲.
10. **پیکربندی و Secrets**: `.env` واقعی با `zod` validate در boot (اگر `GEMINI_API_KEY` نبود، سرور در حالت DEMO بالا بیاید و در UI بنویسد). رمزهای تلگرام/اینستاگرام هرگز در `/api/state` برنگردند و از UI هم به‌صورت write-only وارد شوند.

### ۴.۳ جاده‌ی پیشنهادی (۳ فاز)

- **فاز ۰ (۲-۳ روز) — «قابل استفاده و امن»**: بستن RCE، آپلود، CORS و XSS؛ ماسک کردن توکن‌ها؛ زدن `zod` روی ۵ اندپوینت اصلی؛ رفع باگ تحویل‌های تکراری؛ اضافه‌کردن `.gitignore` + `tsc` سبز + `npm audit fix`.
- **فاز ۱ (۱-۲ هفته) — «قابل اعتماد»**: SQLite + صف واقعی + job status + docker-compose + اسکریپت bash + DEMO_MODE + تست‌های دامنه.
- **فاز ۲ (۳-۴ هفته) — «محصول»**: مهاجرت UI به React/TS، Drag واقعی، تقویم جلالی درست، آفلاین TTS/LLM، داشبورد هزینه، انتشار تلگرام واقعی با idempotency.

## بخش ۵ — پیشنهادهای بصری و تجربه کاربری

### آنچه خوب است و باید حفظ شود
پالت برند (`#0A1931` ناوی + `#FFB400` طلایی + `#FF5722` نارنجی) قدرتمند و منسجم است؛ ساختار «اتاق‌ها» با شماره‌گذاری ۱ تا ۹ یک mental model خوب می‌دهد؛ کارت‌های `glass-card` در حالت شب خوب در می‌آیند؛ فرم‌ها در هر دو تم کنتراست درستی دارند (این باگ قبلی درست رفع شده).

### ۱۲ پیشنهاد بصری/UX

1. **RTL واقعی، نه فقط `dir="rtl"`**: عددها، کدهای `ATZ-C-000123` و نام مدل‌ها را با `dir="ltr"` و `unicode-bidi: isolate` جدا کنید تا در متن فارسی به‌هم نریزند (الان در چند جا این کار انجام شده، ولی پراکنده و دستی است — به یک کلاس `.ltr` تبدیل شود).
2. **سیستم توکن دیزاین**: `tailwind.config.js` با `colors.brand.navy`, `colors.brand.gold`, `fontSize` مقیاس‌بندی‌شده و `radius` مشترک. الان حدود ۲۰۰ بار `#FFB400` و ده‌ها `text-[10px]` هارد‌کد شده؛ هر تغییر برند یعنی ویرایش صدها کلاس.
3. **تایپوگرافی**: حداقل اندازه‌ی متن را از `9px/10px` به `12px` ببرید. متن‌های ۹ پیکسلی در پنل DAM و لاگ‌ها عملاً خوانده نمی‌شوند. `line-height` فارسی را به `1.8` برسانید.
4. **سلسله‌مراتب بصری**: در هر اتاق، یک «اکشن اصلی» با رنگ طلایی و بقیه خنثی. الان در هر اتاق ۴ تا ۸ دکمه‌ی رنگی (سبز/آبی/کهربایی/بنفش/قرمز) با وزن برابر هستند و چشم نمی‌داند کجا برود.
5. **بازخورد سیستم به‌جای `alert()`**: `alert` و `confirm` بومی مرورگر در `uploadPuzzleJsonFile`, `saveMasterPrompts`, `expandConcepts` استفاده شده — در یک CMS حرفه‌ای، toast + تاریخچه‌ی اعلان. همچنین برای هر عملیات طولانی، skeleton/لودیِر واقعی نه فقط تغییر متن دکمه.
6. **استودیو باید واقعاً استودیو شود**: بوم ۲۷۰×۴۸۰ پیکسل با ۴ لایه، «Photoshop-Lite» نیست. حداقل: مقیاس‌بندی بر اساس ارتفاع viewport، drag واقعی با `pointer events`, راهنماهای چسبنده (snapping)، undo/redo با command stack، zoom, و پیش‌نمایش هم‌زمان با Remotion (hint: `@remotion/player` — پکیج رسمی و سبک برای پیش‌نمایش درون‌مرورگری).
7. **تایم‌لاین واقعی**: `@remotion/player` + یک تایم‌لاین مبتنی بر frame با zoom، ruler و drag بلوک‌ها. الان «تایم‌لاین» یک نمایش تزئینی از `<div>`هاست و اسکرابر سقف ۳۰ ثانیه‌ی هارد‌کد دارد.
8. **زبان وضعیت یکپارچه**: چهار اصطلاح مختلف برای یک چیز: `blueprint_pending`, «در انتظار تایید الگو», «🟨», «pending». یک `StatusChip` واحد با رنگ و آیکون و متن فارسی ثابت بسازید و همه‌جا از آن استفاده کنید.
9. **خالی‌بودن حرفه‌ای (Empty States)**: الان تقریباً همه‌ی اتاق‌ها در اولین اجرا خالی‌اند، بدون راهنما. برای هر اتاق یک empty state با «قدم بعدی چه باشد» طراحی کنید (مثلاً در گالری: «اول یک بلوک JSON آپلود کن»). همراه با یک «بارگذاری داده‌ی نمونه» برای demo.
10. **تقویم**: به‌جای ۷ ستون گرید بدون تاریخ واقعی، یک تقویم ماهانه‌ی جلالی با `weekStartsOn=6`، `Intl.DateTimeFormat('fa-IR-u-ca-persian')`, نمایش بار بر اساس تاریخ واقعی (نه `includes('D01')`), و drag-and-drop برای جابه‌جایی تحویل‌ها.
11. **دسترس‌پذیری**: کنتراست طلایی `#FFB400` روی پس‌زمینه‌ی ناوی خوب است، اما متن `opacity-75` روی کارت‌های شیشه‌ای به مرز ۴.۵:۱ می‌خورد. `focus-visible` برای دکمه‌ها (الان هیچ نیست)، `aria-label` برای دکمه‌های آیکونی، و پشتیبانی از `prefers-reduced-motion` برای انیمیشن `pulseNode`.
12. **موبایل**: منوی کناری `hidden lg:flex` است ولی بخش بزرگی از ناوبری، جدول‌ها و استودیو در موبایل کار نمی‌کند. اپراتور یک CMS محتوایی اغلب موبایلی است. حداقل یک تب‌بار پایین + حالت فقط-خواندنی موبایل برای گالری و تقویم.
13. **هویت زیربرند**: `brand-config.json` شش زیربرند با رنگ اختصاصی دارد ولی UI فقط `Library` را نشان می‌دهد (تم `#3B5998` هارد‌کد در `updateLiveCanvasPreview`). رنگ اکسنتی هر اتاق باید از پیکربندی زیربرند بیاید تا کاربر واقعاً تفاوت «کتابخانه» و «مجله» و «AI» را ببیند.
14. **دارایی‌های برند واقعی نیست**: تمام پوشه‌های `public/assets/parent/**` خالی‌اند و `BrandLogo` به fallback «AZ» می‌افتد. تا این پر نشود، هر خروجی رندرشده بدون لوگوی برند است.

## جمع‌بندی صریح

پروژه‌ی AtoZ.FnB CMS یک **نمونه‌ی اولیه‌ی جاه‌طلب با هسته‌ی دامنه‌ی درست** است: مدل «۲۴ بلوک → الگو → تأیید → تولید → تقویم → انتشار» واقعاً ارزشمند است و باید حفظ و تقویت شود. اما در وضعیت فعلی:

- **پنج مورد بحرانی امنیتی** دارد که یکی‌شان (RCE) در تست واقعی من قابل بهره‌برداری بود؛
- **سه زنجیره‌ی ارزش اصلی** (AI، صدا، رندر) در محیط غیر-ویندوزی یا بدون کلید کار نمی‌کنند؛
- **یک باگ منطقی قطعی** (دو برابر شدن تحویل‌ها) در ورودی اصلی برنامه وجود دارد؛
- **صفر تست، ۱۱ آسیب‌پذیری critical در وابستگی‌ها، و `tsc` شکسته** دارد.

اگر بخواهم یک جمله بگویم: **این پروژه بیشتر «یک دموی بسیار خوب برای ارائه» است تا «سیستمی که می‌توان به آن سپرد».** با حدود ۲-۳ روز کار روی امنیت و باگ‌های منطقی، و ۲-۳ هفته روی لایه‌ی داده/صف/تست، می‌تواند به یک ابزار واقعاً حرفه‌ای برای تولید محتوای F&B تبدیل شود — و پایه‌ی فکری‌اش از الان درست چیده شده است.
